# Execute reusable query plans by callback

The ECS Core represents queries as reusable lazy plans executed through an `each(Entity)` callback instead of exposing component tuples through a standard iterator. Every plan is created with at least one required Component Key, so each execution can choose the smallest required store from current World state without exposing the Entity allocator as a special all-entity driver; without-only and all-entity queries are not supported. Any number of typed Component Stores can participate through membership-only views while Component values remain statically typed and are accessed by the callback. Adding required or excluded constraints returns an independent plan rather than mutating its source. The World tracks active executions so nested read-only queries remain valid while spawn, despawn, registration, Component insertion or removal, and clearing raise a checked error; replacing an existing Component is allowed, and callback failure must not leak the execution guard.
